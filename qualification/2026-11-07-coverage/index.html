    First-party coverage and risk review — 7 November 2026

    The current local campaign passes 35/35 complete CTest groups and measures 81.30% line, 88.95% function and 78.80% branch coverage with Clang/LLVM 23.1.4. Initial coverage was 57.54%/72.81%/52.47%. These figures include every compiled first-party source/header mapping; no first-party exclusion was added. Coverage supports the independent numerical studies, rather than proving their scientific correctness by itself. Native CI acceptance is recorded separately.

    Scope and measurement integrity

    tools/coverage.py owns configuration, instrumentation, the full suite, profile merge, LLVM JSON, annotated HTML and per-module summaries. It inventories all src/*.cpp and include/JoSIM/*.hpp, including files with no compiled mapping. Only vendored solvers, vendored include/spline.h, generated code and test implementation are excluded. Solvers remain instrumented in sanitizer runs. Declarations, disabled preprocessor paths and uninstantiated templates do not acquire executable counters; they are not silently reported as covered.

    The shared CTest validator requires exact declared/executed inventories, unique names, all twelve required regression groups and no skipped/failed cases. Release, library and coverage owners use the same contract. Tool-regression methods test false-success cases, stale data and coverage/mapping failures. Public-download contracts later extend the same qualification group. The first Windows run exposed native separators in the report inventory; paths are now canonical / names. All eight guard methods pass on the supplied native Windows host with Python 3.12.10. The full CI rerun remains a separate gate.

    LLVM 23 reports 48 unused zero-hash mappings, representing 31 unique inline functions. The owner retains the diagnostics and verifies every live profile record against the exact exported execution count. Nonzero-hash mismatches, missing live records, count disagreements or unclassified warnings fail the campaign. Dense/sparse merging was independently checked to preserve totals. One reporting attempt incorrectly combined LLVM's debug output with JSON; its failed evidence remains. The corrected owner separates those passes.

    Requirements set before the current measurement

    • Overall: at least 75% lines, 80% functions and 60% branches.
    • Eleven critical implementation owners: at least 80% lines and 65% branches.
    • Review uncovered critical decisions; percentages alone do not close a gap.
    • Preserve all first-party mappings and reject incomplete/skipped test runs.

    The first expanded campaign reached only 73.77% lines. It was not accepted by lowering the requirement. Meaningful additions cover PWS/EXP closed forms, piecewise invalid grids, malformed sparse arrays, control-block parsing, sanity counts, file-format data/units, and the linear networks below. The piecewise work exposed F27, which was repaired before accepting the later campaign.

    The reviewed policy also detects a drop exceeding 0.5 percentage point overall or 2 points in a critical module from the accepted reference. The smaller-module allowance accounts for a few source/counter changes; the independent floors still apply. References are specific to an LLVM major. An unreviewed major fails until its report and risk assessment are accepted; the tool never generates a passing reference from its own result.

    tools/check_coverage.py also checks the current source hash, complete file/test inventories, mapping validation, counter arithmetic and module/overall agreement. tools/coverage-policy.json records the reviewed limits. The native release workflow requires the coverage job as well as its binary/library/utility jobs.

    High-risk additions

    • Lossless matched line: 36 cases, two modes, two exact-grid timesteps and all grounded/reversed/floating port combinations. Matched source/load impedances imply half-amplitude input and an 8 ps delayed output with no reflected wave. Voltage error is below 2 nV; currents satisfy the 50 Ω port laws within 0.1 nA. Measured maximum voltage error is about 3.51e-17 V.
    • Controlled sources: 72 E/G/F/H cases, both modes and nine port combinations. Independent voltage/current gain laws and the 1 kΩ load establish signed transfer and current. Bounds are 2 ppm plus 0.1 nV, allowing six-digit output formatting; measured maximum voltage error is about 3.59e-15 V.
    • Capacitor orientation: 12 reversed/floating RC cases in both modes at two timesteps. The analytic ramp response, KCL and refinement protect history and sign handling. The conservative voltage envelope is 2*(a*tau)*(h/tau)^2 + 1 nV; halving the step must reduce error below 40% of its previous value plus the output-rounding allowance.

    These supplement the existing analytic RLC, junction/buffer/phase/startup, thermal/colored-noise, SQUID and model-IV studies. They do not establish every SPICE dialect or every physical parameter regime.

    Remaining gaps and assessed limits

    Area Remaining counters Assessment
    Solver resources KLU defaults/analysis allocation failures, some refactor/solve failures and bad_alloc Checked allocation results and RAII are reviewed; repeated singular/invalid-state recovery and leak checks execute cleanup. Tests do not induce host OOM or claim recovery from an OS kill.
    Mode/topology guards Final enum alternatives, short-circuit combinations and singular ground-to-ground source fallbacks Constructor/index invariants are reviewed. Both modes and valid grounded/reversed/floating numerical paths are exercised; zero branch counts can describe correlated predicates, not an unexecuted statement.
    Source/model edges Some diagnostic aliases, verbosity warnings, custom-file fallback and exact analytic-limit guards Main accepted/domain-error paths have independent tests. Standard-library function wrappers, impossible enum states and exact floating-point limit predicates are reviewed without claiming every diagnostic spelling is executed.
    Legacy subcircuit helpers Some four-node/JJ token substitutions and pre-parsed-model fallback paths Retained compatibility helpers are inspected against constructor token positions; common legacy binding and the supported parameter-aware path are tested. These counters stay visible; no universal compatibility claim is made.
    Formatting and public helpers Some progress/verbosity variants, empty manually populated traces and unused getters/hooks Data/units and destination failures are checked for CSV/DAT/RAW/stdout; progress has separate timing and worker-lifetime evidence. Direct public-container mutation must preserve the documented API invariants.

    The raw branch inventory retains exact locations/counts. It includes individual short-circuit predicates; several can share one source line. Remaining cases are retained limitations or reviewed guard/helper variants, not excluded code. No unexplained high-risk integration, history, noise or repaired-defect path is being accepted on a smoke-test result alone.

    Reproduction and evidence

    From the repository root, use matching Clang, llvm-cov and llvm-profdata majors:

    python3 -B tools/coverage.py --build-dir build/coverage --output artifacts/coverage
python3 -B tools/check_coverage.py --summary artifacts/coverage/summary.json \
  --output artifacts/coverage/policy.json

    Use fresh campaign paths. --initial-cache can reuse verified dependency sources. CI selects matching Ubuntu Clang/LLVM 18 tools explicitly. Its initial 35-group report passes the same risk floors and mapping checks, with 81.32%/88.95%/78.77% overall coverage. The reviewed major-18 reference uses the two-decimal values published in CI42307801289; exact counters remain in its machine-readable artifact. A subsequent native/guard run is still required. A report from another source tree cannot pass the current-source guard merely because its percentages are high.

    artifacts/audit-resolution/coverage-policy/ retains exact commands, source/tool identities, all module counters, mapping validation, test inventories/JUnit, annotated HTML, the policy decision, numerical receipts and exact owners. Earlier campaigns remain separate, including the missed target and failed JSON reporting witness. Final integrated/source-version/native checks remain required.
