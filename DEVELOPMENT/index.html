    Developing JoSIM

    JoSIM uses C++17, CMake and CTest. The default sparse solver is KLU. The obsolete SuperLU selection is retired: -DSLU=ON and manually defining the SLU macro produce explicit errors. Use KLU; the earlier accepted option did not select a functioning alternative. JoSIM no longer downloads, links or installs the unused SuperLU/CBLAS packages. Applications using those packages directly must provide their own dependencies. The default KLU public API is unchanged. The inactive OpenMP placeholder is also retired: -DUSING_OPENMP=ON fails explicitly. There is no parallel simulation implementation.

    Build and test

    Use a C++17 compiler, CMake 3.21 or newer, and Python 3 for these commands and the regression suite. CTest 3.21 provides the JUnit output required by the qualification owners; the declared minimum follows this tested workflow.

    From the repository root:

    cmake -S . -B build/dev -DCMAKE_BUILD_TYPE=Release
cmake --build build/dev --config Release --parallel 4
ctest --test-dir build/dev -C Release --output-on-failure --timeout 90

    Configuration downloads checksum-verified solver archives. To prepare sources before an offline build:

    cmake -DJOSIM_DEPENDENCY_DIR=build/dependencies -P cmake/prepare_dependencies.cmake
cmake -S . -B build/dev -C build/dependencies/sources.cmake

    The generated sources.cmake contains absolute paths. Regenerate it when moving the dependency directory to another machine or mount point.

    Regression coverage

    CTest runs the existing circuit examples and focused regression groups:

    • regression::gate: gate units, both analysis modes, subcircuits and IV sweeps.
    • regression::noise: seeded replay, white-noise variance, colored spectra, flux units, fractional critical-current noise and phase-step reduction. Multi-seed white/colored PSD and variance bounds are derived in the white/thermal and colored-noise studies. Colored tests cover five exponents, band shifts across 1 Hz, delay, skipped ticks, process-count limits, both-mode fractional injection and clipping.
    • regression::cli: invalid transient settings and recursive subcircuits.
    • regression::functions: waveform alignment, interpolation and expressions.
    • regression::junction_numerics: raw constant-bias JJ phase accumulation, constitutive current and conservation over multiple lengths/timesteps; current-driven RSJ equilibrium, periods and averaged pulse areas. See the phase study.
    • regression::numerics: independent analytic RC/RL/RLC responses, KCL/KVL, timestep refinement and comparison of both modes with warm/cold startup; an independently derived biased JJ/inductor equilibrium checks flux history. Analytic precharge/discharge and beta_c conversion examples are also required; see the model-boundary study. Floating-primary/reference and external-loop-flux checks cover #107/#108; see the SQUID study. See the linear-circuit study.
    • regression::buffer: finite-capacitance switching in the #101 buffer, independent continuous references, flux conservation and timestep refinement. See the buffer study.
    • regression::sweep: safe fresh-process circuit sweeps, source preservation, independent Ohm/RSJ means, include/custom paths, failures and timeouts. See the sweep guide.
    • regression::build_options: retired solver/parallel configuration and macro rejection.
    • regression::library: repeated recoverable errors followed by valid runs.
    • regression::installed_package: installs the library, then builds and runs a fresh external C++ consumer using find_package(josim 3.0 CONFIG REQUIRED).

    The tests establish these bounded contracts. They do not establish general SPICE compatibility or explain every undocumented long-run artifact. Preserve failing numerical evidence before changing device equations.

    Optional scientific references

    The plotting and phase-specification utilities have a separate pinned environment and runtime suite. See Python utilities for installation, headless image export and the CI release gate. Their dependencies are not needed for the standard-library Python tests in the native CTest suite.

    Native CTest uses Python's standard library and versioned independent fixtures. Regenerating the buffer reference or its plots additionally needs the pinned scientific packages below. Use Python 3.11 or newer; the qualified environment was Python 3.12.12. Keep this environment separate from the legacy build tools.

    python3 -m venv build/science
build/science/bin/python -m pip install -r tools/requirements-qualification.txt
build/science/bin/python -B tools/qualify_buffer.py \
  --binary build/dev/josim-cli --output artifacts/buffer-101 --plot
build/science/bin/python -B tools/qualify_squid_noise.py \
  --binary build/dev/josim-cli --output artifacts/squid-noise

    This checks a separate Kirchhoff/RCSJ ODE using tightened Radau tolerances and an independent BDF method, then compares both JoSIM modes at four timesteps. Plots use a headless backend and a temporary task-owned font cache. See the fixture guide before regenerating checked-in data.

    Coverage and sanitizers

    Use matching major versions of Clang, llvm-cov and llvm-profdata. The coverage owner builds an instrumented Debug application/library, runs CTest, and produces annotated HTML, raw LLVM JSON, per-module summaries and exact commands. Use a dedicated build directory for each campaign; existing execution profiles are preserved rather than silently combined with a later run.

    python3 -B tools/coverage.py \
  --build-dir build/coverage --output artifacts/coverage

    Add --initial-cache build/dependencies/sources.cmake to reuse prepared solver sources. Versioned tools can be selected with --cc, --cxx, --llvm-cov and --llvm-profdata. Coverage includes all compiled first-party src/*.cpp and include/JoSIM/*.hpp mappings. Solvers, the vendored spline header, generated code and test implementation are excluded. Files without mappings remain in the inventory; declarations, disabled preprocessor paths and uninstantiated templates do not acquire executable counters. Review LLVM diagnostics before accepting measurements. Coverage percentages do not establish numerical correctness.

    For memory and undefined-behaviour checks with GCC or Clang:

    cmake -S . -B build/sanitizers -DCMAKE_BUILD_TYPE=Debug \
  -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ \
  -DJOSIM_SANITIZERS=ON
cmake --build build/sanitizers --parallel 4
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 \
UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 \
  ctest --test-dir build/sanitizers --output-on-failure --timeout 120

    This instruments the C solver dependencies as well as first-party code. Runtime link requirements propagate to installed development consumers. Instrumentation is disabled by default and is not used for release packages. LeakSanitizer needs process inspection that some sandboxes prohibit; run in a suitable environment instead of disabling leak checks or changing host security settings.

    Check the completed report against the reviewed policy:

    python3 -B tools/check_coverage.py --summary artifacts/coverage/summary.json \
  --output artifacts/coverage/policy.json

    The coverage study records the independent risk floors, remaining gaps and per-compiler regression limits. The guard rejects stale source, incomplete tests, changed mapping scope and unreviewed LLVM majors. CI runs matching Clang/LLVM 18; local qualification also covers major 23. The coverage job is a tagged-release prerequisite. Percentages supplement the numerical/error assertions and do not establish scientific accuracy.

    Installed C++ library

    cmake --install build/dev --config Release --prefix build/install

    Consumers set CMAKE_PREFIX_PATH to that prefix, call find_package(josim 3.0 CONFIG REQUIRED), and link josim::josim. The package loads its solver dependencies and propagates C++17 and public headers. See embedding guidance for error recovery and random-state ownership.

    Supported source-library configurations:

    Configuration Result
    Default Static JoSIM and KLU libraries; platform's default C++ runtime
    -DBUILD_SHARED_LIBS=ON Shared JoSIM with static, position-independent KLU dependencies
    -DMAKING_STATIC_BUILD=ON Static JoSIM/KLU; static MSVC runtime on Windows, static C++ runtime with GNU/Linux

    The last two options are mutually exclusive. macOS keeps its system runtime. These options do not promise a fully static executable including glibc. Shared solver DLLs are not part of the supported package: the old wrappers lack that interface. JoSIM's shared-library mode retains the same KLU backend.

    The installed CLI locates shared JoSIM relative to its own installation. External Windows applications must make the installation's bin directory available to their DLL loader. Do not mix headers, DLLs and import libraries from different builds.

    Reproduce the library-mode CI checks with:

    python3 -B tools/verify_library.py --build-root build/library \
  --dependencies build/dependencies --output artifacts/library

    On Windows add --generator "Visual Studio 17 2022". Add --modes static to check the static-runtime configuration separately. Each mode runs all declared CTest tests, refuses missing/skipped tests, moves the installation into a path with spaces, removes the original prefix, builds fresh external consumers and checks the relocated CLI's loader path. Summary JSON records source, toolchains, commands and test counts. CI covers default/shared libraries on all five native targets; release packaging also checks each target's declared runtime policy.

    Legacy GNU toolchains need stdc++fs for C++17 filesystem functions. A link probe retains that public requirement only where needed by JoSIM and its headers; modern toolchains no longer receive the stale unconditional link flag.

    Keep fixes focused and add regression checks for non-trivial defects. Record user-visible behavior in CHANGELOG.md. See the release procedure for portable binary builds.

    Build and check the manual

    Use Python 3.11+ in a separate environment. The documentation dependencies are independent of the numerical/plotting utilities:

    python3 -m venv build/documentation-env
build/documentation-env/bin/python -m pip install -r tools/requirements-docs.txt
build/documentation-env/bin/mkdocs build --strict --site-dir build/documentation
build/documentation-env/bin/python -B tools/check_docs.py \
  --site-dir build/documentation --output artifacts/documentation/links.json

    On Windows use the corresponding executables under build/documentation-env/Scripts/. The site excludes ignored docs/context/ notes. Local file/anchor checking is separate from external URL and browser checks. Math rendering uses pinned MathJax 3.2.2 and targets modern browsers; no legacy polyfill is loaded.
